# The Daily Tape

A simple, static site for TCU's Neeley Equity Research Club. Plain HTML/CSS/JS,
generated from Markdown content, plus one Vercel Serverless Function that runs
every trading morning to write the homepage's Today's Brief, generate each
pod's daily sector brief, and refresh live security quotes.

## How it's put together

- **Static pages** (`public/`) are generated by `scripts/build.js`, which reads
  `content/pods/*.md`, renders each pod's updates through the shared template
  in `templates/partials.js`, and writes plain HTML into `public/`. Nobody
  hand-edits HTML — the nav/header/footer live in one file.
- **Pod content** is one Markdown file per pod in `content/pods/`. Every
  trading morning, the daily cron writes a new AI-generated brief into each
  pod's file automatically (see "How sector briefs are generated" below) — a
  club member never has to write one by hand, though the file remains a plain
  Markdown file anyone can still edit directly for manual curation (pinning a
  pod, flagging a Watchlist, marking sample content).
- **Archive** (`archive.html`, a primary tab in the masthead) aggregates every
  entry from every pod into one newest-first feed. Nothing new to store — it's
  generated at build time from the same markdown files.
- **About** (`about.html`, also a masthead tab) explains what the site is, how
  the daily automation works, and where its data comes from.
- **"Pin to your homepage"** is a personal star next to the pod name on each
  pod page. Since the site has no login or database, this is a per-browser
  preference stored in `localStorage` (`src/js/pod-star.js`) — it reorders
  the pod grid for that visitor only. It's separate from the editorial
  `pinned: true` frontmatter flag pod leads can set (see below), which
  changes the order for everyone.
- **"Securities to Note"** is a sidebar on each pod page listing tickers
  flagged as important that day, each with a live-ish current price. Prices
  come from `data/watchlist-quotes.json`, fetched client-side
  (`src/js/watchlist-quotes.js`) and written by the same daily cron job that
  updates Today's Brief (see below).
- **Market Pulse** (S&P 500, Dow, Nasdaq, 10-Year Treasury, VIX, and a short
  news headline/deck), the Watchlist quotes above, and every pod's daily
  sector brief are all written by one daily cron job
  (`/api/update-market-pulse`), which commits everything straight back to
  this repo. Pages fetch the JSON pieces client-side — no database, no server
  needed at page-load time.

```
content/pods/*.md            <- rewritten daily by the cron; still hand-editable for curation
data/nyse-holidays.json      <- update once a year by hand
data/market-pulse.json       <- overwritten automatically by the cron function
data/watchlist-quotes.json   <- overwritten automatically by the cron function
lib/parse-pods.js            <- markdown parsing/writing shared by the build script AND the cron function
scripts/build.js             <- generates public/ (incl. archive.html, about.html) from content/pods + src
templates/partials.js        <- the ONE place nav/header/footer markup lives (and the PODS/bellwethers roster)
src/css, src/js              <- static assets, copied into public/ as-is
src/js/pod-star.js           <- personal "pin to your homepage" star (localStorage only)
src/js/watchlist-quotes.js   <- fetches/renders live prices in the Securities to Note sidebar
api/update-market-pulse.js   <- daily cron function
api/lib/                     <- isolated helpers (trading-day check, Finnhub client, Anthropic client, GitHub commit)
public/                      <- build output (gitignored, regenerated on every build)
```

## Running it locally

You need Node.js 18+ (for built-in `fetch`). There are no npm dependencies to
install.

**Static site only** (no API function, fine for checking layout/content changes):

```bash
npm run build        # generates public/
npx serve public     # or open public/index.html directly in a browser
```

**Full local dev, including the cron function** — install the Vercel CLI and run:

```bash
npm install -g vercel
vercel dev
```

`vercel dev` reads `.env.local` automatically and lets you hit
`http://localhost:3000/api/update-market-pulse` directly to test it without
waiting for the actual cron.

## Environment variables

Copy `.env.local.example` to `.env.local` for local dev:

```bash
cp .env.local.example .env.local
```

| Variable | Purpose |
|---|---|
| `FINNHUB_API_KEY` | Market data (indices, treasury yield proxy, VIX, news) |
| `ANTHROPIC_API_KEY` | Writes each pod's daily sector brief from real news headlines |
| `GITHUB_TOKEN` | Lets the cron function commit updated files back to this repo |
| `GITHUB_REPO` | `owner/repo-name` for this repo |
| `GITHUB_BRANCH` | Branch to commit to (defaults to `main`) |

In production, add the same variables under **Vercel Dashboard → your project
→ Settings → Environment Variables**. `.env.local` is gitignored and never
read in production — Vercel only uses its own dashboard-configured env vars.

### Getting a Finnhub API key

1. Go to [finnhub.io/register](https://finnhub.io/register) and create a free account.
2. Copy your API key from the dashboard.
3. Put it in `.env.local` (`FINNHUB_API_KEY=...`) for local dev, and in the
   Vercel project's environment variables for production.

The free tier is generous enough for one API call a day. If Finnhub's index
coverage or pricing ever changes, `api/lib/market-data-finnhub.js` is the only
file that needs to change — see the comment at the top of that file for how to
swap in a different provider (Alpha Vantage, Twelve Data, Financial Modeling
Prep, etc.) without touching the rest of the codebase.

### Getting an Anthropic API key

1. Go to [console.anthropic.com/settings/keys](https://console.anthropic.com/settings/keys) and create a key.
2. Put it in `.env.local` (`ANTHROPIC_API_KEY=...`) for local dev, and in the
   Vercel project's environment variables for production.

This powers `generateSectorBrief()` in `api/lib/anthropic-client.js`, which
writes each pod's daily brief from real news headlines pooled across three
representative "bellwether" tickers per pod (see the `PODS` array in
`templates/partials.js`) — news from several companies, not one, is what lets
the model write about the sector broadly instead of a single company's story.
It defaults to a fast, inexpensive model (`claude-haiku-4-5-20251001`) since
this is a short daily writing task running across seven pods in one function
invocation — swap the `MODEL` constant in that file for a stronger model if
the writing quality needs improving.

### Creating a GitHub personal access token

The cron function commits a file to this repo on your behalf, which needs a
token with write access:

1. Go to **GitHub → Settings → Developer settings → Personal access tokens →
   Fine-grained tokens** and click **Generate new token**.
2. Set **Resource owner** to your account/org, and under **Repository access**
   choose **Only select repositories** → this repo.
3. Under **Permissions → Repository permissions**, set **Contents** to
   **Read and write**. That's the only permission needed.
4. Generate the token and copy it immediately (GitHub only shows it once).
5. Put it in `.env.local` as `GITHUB_TOKEN=...` for local testing, and add it
   to the Vercel project's environment variables for production.
6. Also set `GITHUB_REPO` (e.g. `your-github-username/nerc-pod-website`) and,
   if you don't use `main`, `GITHUB_BRANCH`.

(A classic personal access token with the `repo` scope also works if you
prefer, but a fine-grained token scoped to just this repo is safer.)

## How sector briefs are generated

Nobody needs to hand-write a pod's daily entry. Every trading morning, the
same cron job that updates Today's Brief also:

1. Fetches recent news for each pod's three "bellwether" tickers (the
   `bellwethers` field on each pod in the `PODS` array in
   `templates/partials.js` — e.g. `JPM`, `BAC`, `PLD` for Financials & Real
   Estate) and pools the headlines together. Using several companies instead
   of one is what lets the brief read as sector-wide commentary rather than a
   single company's news recap.
2. Asks Claude (`generateSectorBrief()` in `api/lib/anthropic-client.js`) to
   write a headline and a two-paragraph analysis about the sector broadly —
   specific companies can be mentioned as supporting examples, but the piece
   isn't supposed to center on just one of them. It's instructed not to
   invent facts beyond what the headlines actually say.
3. Prepends the result as a new dated entry in that pod's
   `content/pods/<slug>.md` (`prependEntry()` in `lib/parse-pods.js`), citing
   the real news outlets (Reuters, Bloomberg, etc.) the headlines came from as
   `Sources:`, and commits the updated file back to the repo.

A club member can still add or edit an entry by hand in the same file, using
this format — useful for a one-off manual note, or just to see the format:

```markdown
## 2026-09-20
**Your headline here**
A few sentences of analysis.
Tickers: $AAPL, $MSFT
Sources: Reuters, Bloomberg
```

- The date must be `YYYY-MM-DD` and go on a line starting with `## `.
- The headline goes on its own line wrapped in `**double asterisks**`.
- The `Tickers: ...` line is optional. List them space- or comma-separated
  with a `$` prefix (e.g. `$PNC, $KEY`).
- The `Sources: ...` line is optional but strongly encouraged — it renders as
  a small citation line under the entry.

Any manual edit just needs to be committed and pushed to `main`; Vercel
rebuilds the site automatically.

### Flagging "Securities to Note"

Each pod page has a sidebar for securities that are important or likely to
move today — separate from the dated entries below. Add an optional
`## Watchlist` section anywhere in your pod's markdown file:

```markdown
## Watchlist
- $JPM: Reports Q3 earnings before the open
- $KEY: Shareholder vote on the merger today
```

Each line is `- $TICKER: short note` — the ticker becomes the sidebar's bold
line, the rest becomes the note underneath it. If a pod has no `## Watchlist`
section, its page simply doesn't show a sidebar that day.

Each ticker also gets a live-ish current price next to it. Every trading
morning, the same cron that updates Today's Brief scans every pod's
`## Watchlist` section, fetches a quote from Finnhub for each ticker it
finds, and writes the results to `data/watchlist-quotes.json`. There's
nothing to configure per-pod for this — just add the `## Watchlist` section
and a price shows up automatically the next time the cron runs. (Until then,
or if a ticker is misspelled and Finnhub can't resolve it, that ticker's
price is just left blank rather than breaking the page.)

### Pinning your pod to the top of the nav

By default, pods are listed alphabetically in the nav bar and on the homepage
grid. If your pod lead wants their pod pinned to the front instead (e.g.
during a week your sector is especially active), add a line to that pod's own
frontmatter:

```markdown
---
pod: Technology
pinned: true
---
```

No admin panel, no config file elsewhere — it's just a flag on your own
file, same as everything else in the content model. If more than one pod sets
`pinned: true`, they'll all appear at the front, in alphabetical order among
themselves.

### Marking a pod's content as sample/placeholder

The Financials & Real Estate pod ships with sample entries so you can see the
format in action. Its frontmatter has `sample: true`, which renders a small
"these are sample entries" banner at the top of that pod's page — so nobody
mistakes placeholder content for real research. Once a pod lead replaces the
sample entries with real briefs, delete the `sample: true` line.

## Daily cron automation — how it all runs

`vercel.json` schedules `/api/update-market-pulse` to run once a day via
Vercel Cron:

```json
"crons": [{ "path": "/api/update-market-pulse", "schedule": "30 13 * * *" }]
```

On each run, the function:

1. Checks `data/nyse-holidays.json` and the day of week to see if today is a
   US trading day. If not (weekend or holiday), it exits immediately and does
   nothing.
2. If it is a trading day, it fetches the S&P 500, Dow, Nasdaq, 10-Year
   Treasury yield, VIX, and a top headline/deck from Finnhub, and writes that
   to `data/market-pulse.json`.
3. It scans every pod's markdown file for a `## Watchlist` section, fetches a
   quote for each ticker it finds, and writes those to
   `data/watchlist-quotes.json`.
4. For each of the seven pods (in parallel), it fetches recent news for that
   pod's three bellwether tickers, pools and dedupes the headlines, asks
   Claude to write that pod's sector brief broadly from them, and prepends
   the result into that pod's own `content/pods/<slug>.md`. One pod's failure
   (bad news feed, model hiccup) is caught and logged without blocking the
   other six.
5. Every file above is written **by calling GitHub's "create or update file
   contents" REST API** — a real `git commit` isn't possible from inside a
   serverless function, so this is the standard workaround. Each write is a
   normal push to `main`, which triggers Vercel's regular git-integration
   auto-deploy. The rebuild copies the fresh JSON into `public/data/` and
   regenerates every pod page with its new entry.

Because steps 3–4 read `content/pods/*.md` directly off disk at runtime (via
a dynamically-built file path, not a static `require()`), Vercel's automatic
function file-tracing can miss those files. `vercel.json` works around this
with an explicit `functions.includeFiles` entry for this function, and also
raises `maxDuration` to 60 seconds to give the seven parallel Finnhub+Claude
round trips enough headroom:

```json
"functions": {
  "api/update-market-pulse.js": { "includeFiles": "content/pods/**", "maxDuration": 60 }
}
```

If you ever see watchlist quotes or sector briefs silently not updating in
production while Today's Brief keeps updating fine, check this config first —
it usually means the content files didn't make it into the deployed function
bundle, or the function is timing out before all seven pods finish.

### Two things to know about the cron schedule

**1. It drifts by an hour across Daylight Saving Time changes.**
`13:30 UTC` is 1 hour before the 9:30 AM ET market open only while the US is
on Eastern Daylight Time (roughly mid-March to early November). During
Eastern Standard Time (roughly early November to mid-March), 13:30 UTC is
8:30 AM ET — two hours before open instead of one. Vercel cron schedules are
fixed in UTC and don't shift for US daylight saving automatically.

**Twice a year** (after the clocks change in mid-March and early November),
nudge the hour in `vercel.json` by ±1 if you want to keep it at ~1 hour before
open: `12:30 UTC` in the winter, `13:30 UTC` in the summer. This manual nudge
is simpler than trying to encode DST-aware logic into a single cron
expression. (This is also called out as a code comment at the top of
`api/update-market-pulse.js`.)

**2. Vercel Hobby plan cron limits.**
The Hobby (free) plan allows only **one cron run per day**, and Vercel
documents cron timing precision as approximate — within roughly ±59 minutes
of the scheduled time, not exact-to-the-minute. Don't be alarmed if this
doesn't fire at the exact same second every day; that's expected behavior on
Hobby, not a bug. If you ever need multiple runs per day or tighter timing
precision, **Vercel Pro** supports more frequent and more precise cron
scheduling.

### Updating the NYSE holiday list

`data/nyse-holidays.json` is a plain list of full-market-close dates, keyed by
year. Once a year (e.g. every December), add next year's dates from
[nyse.com/markets/hours-calendars](https://www.nyse.com/markets/hours-calendars)
and optionally remove years that have fully passed. No API, no dependency —
just hand-edit the JSON.

This same file is also copied into `public/data/` at build time and fetched
client-side by `src/js/market-pulse.js`, which checks — fresh, on every page
load — whether *today* is actually a trading day (mirroring the weekday +
holiday-list check `api/lib/nyse-calendar.js` does server-side). If it isn't,
a banner appears above Today's Brief explaining that markets are closed and
that the content shown is from the most recent trading day. This is computed
independently of whether the cron actually ran that morning — the cron
doesn't write anything on non-trading days, so relying on stale server state
alone wouldn't reliably catch every weekend/holiday. Keep this file
up to date and both checks stay in sync automatically, since they read the
same source of truth.
